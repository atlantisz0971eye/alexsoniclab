# 独立站：可调参数规划

> **进度（2026-11-08）**：A、B、C、D 四层都已实现，AI DJ 也做了，用的是基于种子的随机演奏，不是模型（见 README「参数」「AI DJ」）。还没做的是第五节阶段 3 里的「保存/分享命名预设」和「双站对打」。下文保留最初的规划，和实现有出入的地方：
> - 每个 player 的音量回来了，在抽屉的 C 层（`arch` `typ` `head` `photo` `link`），控制台没动。
> - 鼓型做成了四种预设：风格自带 / FOUR / BROKEN / HALF。
> - 列数（`cols`）通过缩放字号实现，固定字符数铺满屏幕。

目标：让访客（和你自己）能调更多东西，但不弄乱作品集的控制台，也不让服务器成本失控。

## 一、先分清四层

参数作用在不同的地方，代价也不同，所以按层来设计：

| 层 | 在哪里算 | 改了以后 | 代价 |
| --- | --- | --- | --- |
| **A 读取** | 服务器，无头浏览器 | 必须重新扫描 | 每种组合都要单独跑一次 Chromium，单独占一份缓存 |
| **B 映射** | 前端，snapshot → 一行行 ASCII | 立即生效 | 免费 |
| **C 声音** | 前端，synth / 风格 | 立即生效（BPM 在下一小节生效） | 免费 |
| **D 演奏与界面** | 前端 | 立即生效 | 免费 |

原则：**B、C、D 可以放开调；A 只给几个预设档位**，不给自由数字。不然每个不同的数字都会变成一次新扫描，缓存基本命中不了。

## 二、参数清单

### A 读取（服务器，只给预设）

| 参数 | URL 键 | 取值 | 现在 | 说明 |
| --- | --- | --- | --- | --- |
| 视口宽度 | `w` | `390` 手机 / `1280` 桌面 / `1920` 宽屏 | 固定 1280 | 同一个网站在手机上排版完全不同，听起来也不一样。最值得做。 |
| 深色模式 | `dark` | `0` / `1` | 关 | 用 `prefers-color-scheme: dark` 渲染，影响媒体亮度。 |
| 去掉 Cookie 弹窗 | `clean` | `0` / `1` | 关（BBC 会读到弹窗） | 先隐藏常见的同意弹窗选择器，再拍 snapshot。 |
| 等待 | `wait` | `fast` / `normal` / `patient` | normal | 对应约 3 / 6 / 15 秒的加载与懒加载滚动。patient 要把 `maxDuration` 调高。 |
| 读取高度 | `h` | `10k` / `30k` / `60k` | 30000px | 60k 会让 Wikipedia 这类长页的返回体积翻倍（约 1.3 MB）。 |
| 语言 | `lang` | `en` / `zh` / `ja` … | en | 用 `Accept-Language` 和 locale，多语言网站会换内容。 |

实现要点：

- 这些参数进入 `/api/scan` 的查询串，**服务器用白名单校验**，不在名单里的值返回 `bad_url`。
- 规范化 308 时按固定顺序排好参数，CDN 和内存缓存的 key 就是「网址 + 参数」。
- `snapshotPage` 的 `GENERIC_PAGE` 变成 `genericPage({ maxHeight, … })`。共享文件里的作品集默认值不变。

### B 映射（前端）

| 参数 | URL 键 | 范围 | 现在 | 听感 |
| --- | --- | --- | --- | --- |
| 行高（读取粒度） | `row` | 10 / 20 / 40 px | `ROW_PX = 20` | 越小，同一页的音符越密、越长。 |
| 方向 | `dir` | 从上往下 / 从下往上 | 从上往下 | 倒着读一个网站。 |
| 读哪些东西 | `kinds` | 文字、标题、链接、媒体、卡片可分别开关 | 全开 | 比如只留卡片边框，就是纯节奏骨架。 |
| 列数 | `cols` | 自动 / 80 / 120 / 160 | 自动（按屏宽） | 影响 ASCII 粗细，也影响 carve 的精度。 |

实现要点：`readRow(snapshot, index, cols)` 加一个可选的 `options` 参数（行高、要读的种类），作品集不传，结果就和现在一样。

### C 声音（前端）

`SonicStyle` 里已经有这些字段，只是现在写死在每个风格里。做法是「风格 + 覆盖值」：`{ ...styleById(id), ...overrides }`。

| 参数 | URL 键 | 范围 | 来自 |
| --- | --- | --- | --- |
| BPM | `bpm` | 70–160 | `style.bpm` |
| Swing | `swing` | 0–0.6 | `style.swing` |
| 调（根音） | `root` | A、C、D、E… 或 Hz | `style.root` |
| 鼓型 | `kick` / `snare` | 预设：四拍 / 碎拍 / 半速 | `style.kick` / `style.snare` |
| 断鼓 | `breakdown` | 开 / 关 | `style.breakdown` |
| 打字员模式 | `typist` | hats / breaks / clicks | `style.typist` |
| 每个 player 的音量 | `mix` | 0–1 ×5 | `style.mix` 和 `synth.setLevel`（新控制台把推子拿掉了） |
| 延迟 / 混响 | `fx` | 0–1 ×2 | `synth.setSends` |
| 滤波范围 | `filter` | 窄 / 中 / 宽 | `setBrightness` 里的 380–9580 Hz |
| 滚动对滤波的灵敏度 | `sens` | 0.5–2× | 现在是 `speed / 2600` |
| Remix 路由 | `route` | 已有，例如 `architect.text` | `DeckState.routes`（URL 已经能读，控制台上没有按钮） |

### D 演奏与界面（前端）

| 参数 | URL 键 | 说明 |
| --- | --- | --- |
| **自动滚动** | `auto` | 每秒 N 像素自动往下读，不用手滚也能一直放。对独立站最有用：打开链接就是一首曲子。 |
| 读头位置 | `axis` | 屏幕上 20%–60%，现在是 40%。 |
| 循环长度 | `bars` | 1 / 2 / 4 / 8（已有，进 URL）。 |
| 交叉推子曲线 | `curve` | 等功率 / 线性 / 硬切。 |
| 像素模式 | `pixel` | normal / sort / melt（已有，进 URL）。 |
| 配色 | `ink` | 按分区上色 / 单色绿 / 单色琥珀。 |

## 三、界面放在哪里

不改作品集的控制台。独立站多两个面板，都用同样的 ASCII 风格：

1. **扫描前（URL 页）：`[SETUP]` 折叠区**，放 A 层的预设，比如 `WIDTH [390] [1280] [1920]  DARK [ ]  CLEAN [x]  WAIT [fast|normal|patient]`。改了 A 层参数要重新扫描，所以放在扫描之前最自然。
2. **Lab 里：`[PARAMS]` 抽屉**，按 `?` 或点控制台旁边的键打开，放 B、C、D 层，改了立即生效。抽屉由独立站通过插槽属性传给 `SonicLab`（比如 `extraPanel`），作品集不传就没有。

所有参数都写进地址栏，所以一个链接就能完整复现「哪个网站、怎么读、怎么响」，例如：

```
/?url=https://en.wikipedia.org/wiki/Techno&w=390&clean=1&style=acid&bpm=138&row=10&auto=120
```

回放链接（`#perf=`）也要带上这些参数，不然换了行高就对不上。

## 四、代码结构

- 新建 `app/lib/params.ts`，一张表定义所有参数：键、所属层、类型（枚举 / 范围）、默认值、标签。这一张表同时用来：
  - 解析和生成 URL；
  - 服务器校验 A 层白名单，生成缓存 key；
  - 自动生成 SETUP 和 PARAMS 面板（不用每加一个参数就写一遍界面）。
- 共享文件（作品集也用的）只做「加可选参数、不传就和现在一样」的改动：`readRow` 的 options、`SonicLab` 的 `settings` 和 `extraPanel`、synth 接受风格覆盖值。改完照旧在作品集里逐行比对，确认作品集没变。
- 每个参数在 `localStorage` 里记住访客上次的值，链接里带的值优先。

## 五、分阶段

**阶段 1：纯前端，只动独立站和少量共享代码（最快能听到效果）**

- `params.ts` 和 URL 读写
- 自动滚动 `auto`、BPM、swing、根音、行高、读头位置
- Lab 里的 `[PARAMS]` 抽屉
- 验证：每个参数在浏览器里改一次并截图；作品集 snapshot 逐行比对不变

**阶段 2：服务器读取参数**

- 视口 390/1280/1920、深色模式、去 Cookie 弹窗、等待档位
- 白名单校验和缓存 key；`check:security` 加上非法参数的用例
- URL 页的 `[SETUP]`
- 注意成本：每个网站最多变成 3×2×2×3 = 36 种扫描。建议默认只开放宽度和 clean，其他放在「高级」里

**阶段 3：进阶**

- 恢复每个 player 的音量和 remix 路由（放在抽屉里，不放回控制台）
- 鼓型预设、交叉推子曲线、单色配色
- 保存 / 分享自己的预设（命名的一组参数）
- **双站对打**：deck A 读一个网站、deck B 读另一个，用交叉推子混两个网站。新的双 deck 结构天然适合这个，只需要让 deck A 能从第二个 snapshot 取行。

## 六、需要你决定的

1. 阶段 1 先做哪几个：我建议 **自动滚动、BPM、行高、视口宽度**（视口宽度虽然在阶段 2，但最能体现「同一网站不同听感」）。
2. 每个 player 的推子要不要回来？新控制台故意拿掉了，我建议只在独立站的抽屉里提供。
3. 读取高度要不要开放 60k：长页面会更慢、返回更大，Hobby 额度消耗也更快。
